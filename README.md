# Phanto’s Cosplay

Dress for any occasion.

**Start with [HANDOFF.md](HANDOFF.md) before making changes.** It is the authority for current status, user decisions, restrictions and the roadmap; this README is an operational reference. Historical progress/backlog snapshots are under `docs/history/`.

A spooky-cute picker for Phanto’s reactions, costumes, and poses. Search names, characters, franchises, emotions, or keyboard emoticons such as `:-)`, `<3`, and `xD`.

## Run locally

From this folder, run `python -m http.server 8765 --bind 127.0.0.1 --directory dist` and open [localhost:8765](http://localhost:8765).

## Host on your own server

Serve `dist/` as the site root, or upload its contents to a subdirectory. Keep the asset folders beside `index.html`. The files are ready to serve over HTTPS from any static web server. HTTPS enables image clipboard and browser file sharing on supported devices.

After editing Tailwind classes or updating Font Awesome, run `npm ci` and `npm run build` to regenerate the static assets.

Downloads and native file sharing use WebP. Copy puts the image on the clipboard as PNG. Social buttons share pose links on the server where the app is running.

## Share links

On your server at `https://cosplay.julibe.cloud/`, search and filters are encoded in the URL. Use the link button beside the pose count to copy the current view. For example, `/?q=happy&category=Reactions` opens a filtered search, and `/?pose=emoji-joy-cheerful` opens a single pose. The share menu on a costume also offers a character link.

## Install and connect

On HTTPS, use the browser’s **Install app** or **Add to Home Screen** command. Supported browsers may also show an install button in the header. The gallery loads from the server, and offline mode shows a reconnect screen.

`GET /catalog.json` returns the public pose catalog as JSON with `schemaVersion` and `poses`. Each pose has an ID, name, category, and an image `path` relative to the catalog URL. Optional fields include emotion, franchise, and legacy IDs. Other origins may read it (see the JSON API section).

## JSON API

The site also serves a read-only JSON API under `/api/`. It is plain static JSON, regenerated by `node api.mjs` and automatically every time the catalog is rebuilt (`npm run build` or `node pose-assets.mjs`). Start at [`/api/index.json`](https://cosplay.julibe.cloud/api/index.json), which lists every endpoint and the current counts.

| Endpoint | What it returns |
| --- | --- |
| `/api/index.json` | API name, version, last release time, counts, and endpoint URLs |
| `/api/poses.json` | Every pose with full details |
| `/api/poses/{id}.json` | One pose. Old IDs from `pose-renames.json` also resolve here; the response's `id` is the current ID and `requestedId` is the one you asked for |
| `/api/latest.json` | The 50 newest poses |
| `/api/categories.json` | Every category (Reactions, Costumes, Activities, Holidays, Animals, Powers, Assets, Turnarounds, Animation) with pose counts, emotions, franchise types and collections |
| `/api/categories/{id}.json` | One category with all its poses, newest first, for example `/api/categories/costumes.json` |
| `/api/collections.json` | Every collection (one per image folder, such as `game-pokemon` or `emoji-joy`) with its name, type, categories, pose count and cover image |
| `/api/collections/{id}.json` | One collection with all its poses, for example `/api/collections/game-pokemon.json` |
| `/api/franchises.json` | Every franchise name with its type and collections |
| `/api/franchise-types.json` | Anime, Game, Movie, TV and the other franchise types |
| `/api/emotions.json` | Every reaction emotion with pose counts |
| `/api/aliases.json` | Map of old pose ID to current pose ID |

Each pose has `id`, `name`, `category`, `emotion`, `franchise`, `franchiseType`, `collection`, `keywords`, `released`, `image` (`url`, `path`, `type`, `width`, `height`), `animation` (frames of an animated pose, see Animated poses), `link` (the share link that opens the pose in the app), `api`, and `aliases` (its old IDs). Fields that don't apply are `null`.

URLs in the API point at `https://cosplay.julibe.cloud/` (`siteUrl` in `api.mjs`); `image.path` is relative to the site root if you host a copy elsewhere. Cross-site requests are allowed: `dist/.htaccess` (Apache, LiteSpeed) and `dist/_headers` (Netlify, Cloudflare Pages) send `Access-Control-Allow-Origin: *` for the API, `catalog.json` and the pose images. On nginx, add `add_header Access-Control-Allow-Origin * always;` to a `location ~ \.(json|webp)$` block.

## Update the catalog

**Do not run `node catalog.mjs` on a fresh clone until the external source library is restored; absent source PNGs can remove entries.**

Save the individual PNG sprites in the workspace `../squirlce/squirlce-emojis/` directory (outside this Git repository). Put each newly converted WebP in `dist/poses/` with the same filename stem, then run `node catalog.mjs` to regenerate the catalog and move the assets into their prefix folders.

For example, `game-persona-5-joker-posing.webp` is served at `/game/persona-5/game-persona-5-joker-posing.webp`, and `emoji-anxiety-worried.webp` is served at `/emoji/anxiety/emoji-anxiety-worried.webp`. The catalog records each image path. Shared `?pose=` links use IDs and continue to work across file moves.

Publish the complete `dist/` from one commit. Revalidate `index.html` on requests so it can load the matching versioned catalog and scripts. When switching from a previously deployed layout, purge the old HTML cache once.

Use these filename patterns for new sprites.

- Holidays use `holiday-<holiday>-<action>`.
- Anime and TV use `anime-<series>-<character>-<action>` and `tv-<series>-<character>-<action>`.
- Movies, games, comics, and books use their type as the first segment, followed by the franchise, character, and action.
- Music uses `music-<genre>-<action>`. Film and TV genre sprites use `movie-<genre>-<action>` or `tv-<genre>-<action>`.
- Cyberpunk genre sprites use `genre-cyberpunk-<character>-<action>`.
- Standalone costumes, animals, and memes use `costume-`, `animal-`, and `meme-`.
- General reactions use `emoji-<category>-<emotion>`.

When renaming an existing sprite, record the old stem under the new stem in `pose-renames.json` so old shared links still resolve.

## Animated poses

See [animations/README.md](animations/README.md) and [HANDOFF.md](HANDOFF.md) for current grid/rotation requirements. Existing rotations use `preserveCanvas: true`, 24 playback frames and body-aligned scale; do not apply generic trimming to those sources. Star half-turns use 12 frames and remain in Assets.

Animated poses start as a horizontal frame strip: one PNG with the frames side by side, each frame square (for example 8 frames of 640×640 in a 5120×640 strip). To add one:

1. Drop the strip in `animations/`, for example `animations/wave.png`.
2. Optionally give it a name, emotion, search keywords, speed or frame count in `animations/animations.json`, keyed by the file name in lowercase with `_` as `-`: `"wave": { "name": "Wave", "emotion": "Joy", "keywords": "hello hi bye", "fps": 10 }`. Without an entry the name comes from the file name, it plays at 10 fps, and the frame count is width ÷ height.
3. Run `npm ci` once, then `npm run build:animations`.

For unaligned strips the build uses a shared bounding box and fits it into a 320 px square; configured `preserveCanvas` grids keep their authored canvas and alignment. It writes `dist/animated/animated-<name>.webp` (looping animated WebP) plus `dist/animated/frames/animated-<name>/animated-<name>-frame-NN.webp`. It adds each strip to the catalog as an **Animation** pose (unless configured as an Assets animation) with the ID `animated-<name>`, and rebuilds `catalog.json` and the JSON API. Rebuilding the catalog with `node catalog.mjs` keeps animated poses, since they are merged back in from `animations/`.

In the app, animated poses play in the gallery and carry an **Animated** tag. The card's download button saves the animated WebP. The film button opens the pose options, where you can pick **All** (the animation) or any single frame, then download it; a single frame can also be rotated, flipped and copied. Copying an animation copies its first frame, since clipboards hold still images.

In the API, animated poses have `category: "Animation"` (or `"Assets"` for asset animations) and an `animation` object with `fps`, `frameDelay` (ms), `frameCount` and `frames` (each with `index`, `url`, `path`). Other poses have `"animation": null`.

## Release dates

Each pose has a `released` time (ISO 8601, UTC) in the catalog, and the app's filter panel can sort by **Newest first** or **Oldest first** (`?sort=newest` / `?sort=oldest`). Dates live in `release-dates.json`, keyed by pose ID. When the catalog is regenerated, a pose without an entry gets the date its WebP first appeared in git history, or the current time if it is brand new. Edit a value in `release-dates.json` and run `node pose-assets.mjs` to change when a look counts as released.

Cards in the newest batch show a **New** tag: any pose released within 6 hours of the most recent release (`newWindowHours` in `dist/app.js`). The tag moves to each new batch automatically when the catalog is regenerated, and searching `new` lists them.

The filter panel also has **From** and **To** release dates (`?from=YYYY-MM-DD&to=YYYY-MM-DD`, inclusive, in the viewer's local time zone).

## Copy metadata and export selected poses

Each card has Copy title and Copy JSON buttons. JSON contains `name`, `category`, optional `assetType`/`assetGroup` for Assets, and an absolute `imageUrl` (the original WebP, including animation where applicable). Clipboard copy requires HTTPS/localhost and browser permission.

Select two or more card checkboxes to show the bulk pill above the dock. ZIP downloads the original WebPs; JSON downloads an array of the same metadata objects. Selection persists while filtering or switching portals, until cleared or the page reloads. ZIP fetches up to four files at a time and refuses selections exceeding500MB; a failed image cancels the archive instead of silently omitting it.

Export checks: `npm run test:asset-tools`.
